# Installation and project setup

## Supported environment

The integration currently targets macOS and Linux, AI-DLC 2.8.2, TAKT 0.65.0, Bun 1.3.13, and Node.js 22.22.0 or newer. Claude Code is the host plugin environment and the live TAKT provider. The tested Claude Code CLI is 2.1.270.

Install Bun, Node.js, and Git through your usual tool manager. Install the pinned TAKT and Claude Code CLIs:

```sh
npm install --global takt@0.65.0 @anthropic-ai/claude-code@2.1.270
```

For AI-DLC, use the versioned [official release](https://github.com/awslabs/aidlc-workflows/releases/tag/v2.8.2). Its installer provides both the native executable and matching harness runtime:

```sh
curl --fail --location https://github.com/awslabs/aidlc-workflows/releases/download/v2.8.2/install.sh --output /tmp/install-aidlc-2.8.2.sh
sh /tmp/install-aidlc-2.8.2.sh --version 2.8.2
```

Check `aidlc --version` and `takt --version`. An already-installed newer AI-DLC release is not a compatible replacement for this prototype.

## Build and test

From this repository:

```sh
bun install --frozen-lockfile
bun run test
bun run typecheck
bun run build:plugin
claude plugin validate dist/claude
```

Tests prepare a runtime cache with the native `aidlc config` command, then run TAKT with deterministic mock responses. They do not need model credentials. Live experiments require a working Claude Code login and are explicitly selected with `--live`.

## Configure an AI-DLC project

Run the following in the target project before starting Inception:

```sh
aidlc config --harness claude --yes
```

AI-DLC's default Claude settings request Bedrock. If you use standard Claude authentication, remove `CLAUDE_CODE_USE_BEDROCK` and Bedrock-specific `ANTHROPIC_DEFAULT_*_MODEL` values from that project's `.claude/settings.json`. Keep AI-DLC's hooks. Do this before its source assessment; changing project settings later can invalidate that assessment.

Start Claude Code with the built plugin:

```sh
claude --plugin-dir /absolute/path/to/takt-aidlc/dist/claude
```

Run `/aidlc` normally. Use the usual questions and approval gates through Inception.

## Configure the handoff before final approval

The following example matches the constant-change experiment: `src/value.ts` initially exports `answer = 41`, and the requested change sets it to 42 with three tests. Other applications need their own source list and verification script.

Create `aidlc/takt-handoff/` in the target project. Copy:

- `dist/claude/workflows/aidlc-construction.yaml` to `aidlc/takt-handoff/workflow.yaml`.
- This repository's `experiments/native-session/verify-app.ts` to `aidlc/takt-handoff/verify.ts` for the demo application only.

Create `aidlc/takt-handoff/config.json`. Replace `<intent-dir>` with the actual intent directory generated by AI-DLC:

```json
{
  "enabled": true,
  "artifacts": [
    "aidlc/spaces/default/intents/<intent-dir>/inception/requirements-analysis/requirements.md",
    "aidlc/spaces/default/intents/<intent-dir>/inception/practices-discovery/team-practices.md",
    "aidlc/spaces/default/intents/<intent-dir>/inception/units-generation/unit-of-work.md",
    "aidlc/spaces/default/intents/<intent-dir>/inception/units-generation/unit-of-work-dependency.md",
    "aidlc/spaces/default/intents/<intent-dir>/inception/delivery-planning/bolt-plan.md"
  ],
  "sources": ["src/value.ts"],
  "workflow": "aidlc/takt-handoff/workflow.yaml",
  "verifyScript": "aidlc/takt-handoff/verify.ts",
  "provider": "claude",
  "construction": true,
  "disableBedrock": true,
  "timeoutMs": 600000
}
```

All configured files must exist by the final approval. Source paths are individual regular files, not directory globs. The verification script is trusted project configuration; it runs from a frozen copy with the generated workspace as its working directory.

Loading the plugin without `enabled: true` does nothing. `construction: true` installs the bundled command gate into the isolated execution directory. The workflow cannot be run standalone without this setup.

## Approve and inspect the result

After the normal final approval, AI-DLC's conductor runs its approval command. The plugin captures the inputs, checks the recorded approval, parks AI-DLC through its official command, and starts TAKT. The conductor should then stop.

Final approval must be a single command. Do not append `echo`, shell redirection, or command chaining. The plugin rejects recognized compound approval commands before execution and asks the conductor to correct their form.

The hook returns a handoff ID. Inspect it with:

```sh
bun /absolute/path/to/takt-aidlc/dist/claude/scripts/handoff.js status /absolute/path/to/target-project <handoff-id>
```

Results live under `aidlc/takt-handoff/runs/<handoff-id>/`:

- `status.json`: `verified`, `needs_input`, or `failed` when stopped.
- `attempts/1/work/`: generated source, tests, and TAKT reports.
- `attempts/1/verification.json`: final independent test result.
- `attempts/1/control/`: Construction validation records.

A failed run can be retried with `retry` instead of `status`; each retry uses a new workspace and the same frozen inputs. A `needs_input` run requires a decision and, where applicable, a revised Inception handoff. It cannot be forced forward with `retry`.

No automatic merge or deployment happens. Review the generated diff and reports before taking the result into your main project. Do not resume AI-DLC Construction in parallel with the handed-off work.

## Known boundaries

- AI-DLC 2.8.2, state version 8, and a single audit shard are required.
- The host plugin currently supports Claude Code; Codex and tmux are not integration dependencies.
- The expanded workflow runs in one workspace and follows units serially.
- This is not an OS security sandbox for adversarial code running as the same user.
- The native AI-DLC `review-brief` dispatcher failed in the recorded experiment. The bundled read-only `.claude/tools/aidlc-review-brief.ts` worked when invoked directly with Bun; no AI-DLC patch was applied.
- An interrupted process may leave a lock. Inspect the process and run records before attempting recovery; automatic stale-lock removal is not implemented.
